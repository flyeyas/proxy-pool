# V2 迁移门槛补丁 1.6.1

日期：2026-11-20，Asia/Shanghai。

## 发现与处置

v1.6.0 在服务器保持 shadow、小样本完整观察 30 分钟后，扩容核对发现 pending 目标占位可能被统计为已检查。状态层将 deferred、environment_error、unsupported 存为 pending 并保留 last_attempt；旧迁移计算只排除了原始代码，漏掉了持久化占位。它还可能把 HTTP-only、非地区主目标或未知代码计入。

发现时从未执行 active，原生产接口一直使用 legacy。已通过正式 rollback 任务回到 legacy 暂停推进；该任务在 shadow 下不替换旧池，也不删除 V2 诊断数据，Token 和源设置保留。没有改写服务器运行源码或强制 Redis 模式绕过门槛。v1.6.0 发布记录保留并增加迁移提示，修复通过新的 1.6.1 标签与 GitHub 镜像交付。

## 修改范围

- 明确认可完成结果的白名单，只在当前 policy 版本、当前地区主 HTTPS 目标上授予迁移覆盖率。
- 排队/未知/延后/环境/不支持/预算中止不计；HTTP-only 与已知地区的非主目标不能替代主目标。
- 明确的连接失败、目标受限或读取超时仍是一次已完成的失败检查，但不成为可用代理。原 95% 双分母、至少 20 个新鲜合格 HTTP 代理、排空后再次核验、原子切换与备份规则均不放宽。
- 仅修改 helper/validation/migration.py 与 setting.py 的补丁版本号；新增独立回归文件。六协议传输、CA、重定向白名单、目标地址、worker/队列/状态机、前端和持久数据 schema 没有修改。

1. 对原始 v1.6.0 标签的迁移模块运行新增用例：9 项负向用例复现误放行，3 项真实失败终态的正向用例通过。命名空间使用独立真实 Redis，不操作生产池。
2. 修复后本机全量 **634 项通过，28.24 秒**；Python 3.13 本地 Docker 全量 **634 项通过，20.43 秒**，均包含真实 Redis 集成。
3. 新增回归通过真实 repo.commit 产生 pending 占位，而非手工假设存储格式；还覆盖 unknown、未来代码、空代码、deadline_exceeded、HTTP-only、非主目标。失败门槛保持旧 Hash 和 shadow 状态，不生成切换备份；正向迁移只投影真正可用记录并保留完整回滚 Hash。
4. 补丁源码冻结于 e82852385ef211309329c1a35d85560a2e3e7f01；后续文档与发布元数据不得改变受测业务代码。
