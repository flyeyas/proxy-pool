    代理检测 V2 开发记录¶

    开始日期：2026-11-19，Asia/Shanghai。基线：6793a3c，v1.5.1。

    基线¶

    • Python 3.13.13，xiangmu 环境：446 项通过，4 条既有 setDaemon 弃用警告，6.91 秒。
    • 本地 Docker 29.9.3，分配内存约 7.75 GiB、8 CPU；基础镜像 Node 26 / Python 3.13 / Redis 8 已存在。
    • 当前依赖实测：requests 2.34.2、urllib3 2.7.0、PySocks 1.7.1、redis-py 8.1.0。
    • 业务开发前只有 docs/plans 下两份未跟踪方案文件，没有已有业务代码修改。

    实现范围¶

    • V2 数据模型、严格地址/认证解析、结构化采集和跨批次来源合并；地区提示冲突保留为 unknown，较强的主机/出口证据优先。
    • HTTP CONNECT、TLS 代理、SOCKS4/4a/5/5h 的真实 HTTPS 请求，国内 QQ、国外 Google、未知地区独立双目标；GET、严格证书、跳转白名单、有限正文和失败分类。
    • 独立 spawn 网络进程、整轮截止、父进程退出守护；GeoIP 查询使用同一监督机制。
    • Redis 队列、租约、fencing、generation、原子 pop/delete、地区索引、认证信息引用计数；80% 复检与 20% 新候选保留份额，空队列互相借用。
    • 指定端点/目标的异步重检需求可在在途任务中合并；目标健康保护、参考探测、2/5/15 分钟受限退避、协议失败冷却，以及参考过期后的恢复。
    • 独立的配置 fingerprint 和规则版本：调整并发/限流不清空成功证据；规则变化重检，并重建目标健康证据。
    • 兼容旧 HTTP 接口、管理员 V2 API、Vue 管理页、采集代理回用、幂等迁移、全局原子切换与回滚。

    默认仍为 legacy。本文记录 2026-11-20 本地验收完成时点：版本号为 1.6.0，随后进入正式标签与云端上线阶段；实际发布和部署状态以 GitHub Release 与受保护的部署审计记录为准。

    真实公网对照¶

    2026-11-19，通过用户已提供的本机 HTTP 代理采集 Geonode，返回并规范化 500 个候选；声明协议为 HTTP 189、HTTPS 提示 95、SOCKS5 146、SOCKS4 70。候选中的地区仅作为来源提示保存。

    限量抽测 8 个候选：14 个协议检测结果中，12 个连接/读取超时、1 个认证失败、1 个代理层 TLS 异常，没有合格结果。抓取 500 条不能写成新增 500 个可用代理；这些结果也不能证明该批地址在所有网络环境中都不可用。

    同一本机 HTTP 代理的对照：默认连接/读取预算 3/5 秒时 QQ 200、Google 超时；6/8 秒预算时两站均通过，Google 检测约 4.16 秒。说明 HTTP CONNECT 访问 HTTPS 正常，当前海外出口对超时预算敏感。代码默认值未因此偷偷改变，部署时应按实际出口结果配置。

    2026-11-20 最终镜像复核时，Geonode 在默认采集预算及一次临时较长预算诊断中均出现网络超时，未取得候选，不能写成接口正常返回空列表。最新 QQ/Google 对照仍为 3/5 秒时 Google 超时、6/8 秒时两站通过（Google 约 2.685 秒）。公网时点和预算的完整边界见 validation-v2-acceptance.md；不把这些网络观测混入 622 项受控测试的通过数。
